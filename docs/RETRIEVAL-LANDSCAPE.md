# Retrieval architecture review — 2026-10-03

The current MiniLM/FTS pipeline is a reference implementation, not a demonstrated market leader. Its FinQA row lookup and CUAD evidence coverage are retrieval proxies, not end-to-end financial/legal answer accuracy. Authored canaries cannot establish generalization. Optimize against independent evidence and matched budgets, rather than treating these scores as interchangeable with vendor answer scores.

## Research scope and source quality

Reviewed 100 search-result slots across long context, document trees, graph memory, late interaction, modern embedding/reranking models, agentic search, learned sparse retrieval and benchmark protocols. Slots include duplicate results; they are not 100 unique papers. The recent window is 2025-10-03 through 2026-10-03; older foundational work is explicitly included. Search metadata is discovery evidence only: publication dates, licenses and algorithms must be checked against primary sources. This is a broad engineering review, not a claim to have examined every OSS repository.

Inspected executable source from PageIndex, Mafin2.5's evaluator, HippoRAG, Qwen3-Embedding, FlashRAG, AnswerDotAI rerankers and PyLate. The following table distinguishes mechanisms from published claims; rows are candidates, not claims of local reproduction.

## Headline-score audit: Mafin2.5

Inspected immutable [repository commit 1c890d5](https://github.com/VectifyAI/Mafin2.5-FinanceBench/tree/1c890d5e0fd9929953d38282614555847727011d). Its top-level files are README, `eval.py`, two saved answer JSON files and human evaluations. The public source does not implement generation of those saved answers. Each saved output contains 150 examples: 136 `AL` (aligned), 6 `BE` (benchmark error), 5 `MVA` (multiple valid approaches), 1 `SEDC` (same evidence/different conclusion), and 2 `NAL` (not aligned). Counting every category except `NAL` yields 148/150 = 98.7%; aligned-only label accounting is 136/150 = 90.7%, which is **not** an independent reassessment of answer correctness. The repository supplies 14 human-review rows with explanations for non-AL cases. Benchmark corrections and multiple interpretations can be justified, but should be independently adjudicated and reported separately in our protocol.

`eval.py` also asks a model to accept inferred, rounded, superset and reasonable interpretations; its optional hybrid evaluation accepts a case if **any** judge accepts it. This is separate from the published human labels, and is not evidence that the headline score was generated solely by that judge. Neither label accounting nor a permissive judge proves a bad result, but both matter when comparing stricter exact evidence/arithmetic protocols. Do not compare our recall@5 directly with its answer accuracy or claim the OSS tree reproduces the production Mafin system.

Other inspected implementation snapshots: [PageIndex 6d23caf](https://github.com/VectifyAI/PageIndex/tree/6d23caf416858f2ca136840305d1f479a86f6ef7), [HippoRAG 2bfd831](https://github.com/OSU-NLP-Group/HippoRAG/tree/2bfd831417202b49cda9da7973e141a456e16872), [FlashRAG 0e57de4](https://github.com/RUC-NLPIR/FlashRAG/tree/0e57de4394fdbc3133e352f0daff4b87cd7fff74), [Qwen3 44548aa](https://github.com/QwenLM/Qwen3-Embedding/tree/44548aa5f0a0aed1c76d64e19afe47727a325b8f).

## Architecture and evaluation priorities

1. Keep original pages/sections and evidence locators as the source of truth. Add a navigation/read surface and source-ordered packing so precise lookup and scoped long-document reading share the same evidence path.
2. Compare lexical, dense hybrid, late-interaction reranking and modern instruction-aware models on fixed candidate/evidence budgets. Report candidate recall before reranking; a reranker cannot recover evidence outside its pool.
3. Compare explicit retrieve, scoped full-context and bounded iterative navigation routes. Enforce document scope in code, record reads/model calls, and never use summaries or generated clues as primary evidence.
4. Separate financial arithmetic, legal span coverage, biomedical support/refutation, code-symbol search, multi-hop and visual table/page tasks. Preserve negative cases and report abstention/unsupported claims alongside answer accuracy.
5. Freeze prompts/configuration before final held-out tests. Report model revision, training exposure, query/corpus scope, judge policy, token/character budget, indexing cost, cold/warm p50/p95, memory and per-query outputs. Bootstrap paired differences; retain regressions instead of selecting only winning domains.

The July 2026 [GRASP preprint](https://arxiv.org/abs/2607.10463) explicitly combines semantic search, keyword search and paragraph reads under a learned cost/grounding-aware policy. Our bounded navigation tools implement the **action surface**, not its RL-trained policy. The July 2026 Jina v3.5 paper explicitly releases under a **noncommercial** license; it is a research comparator rather than an automatic commercial runtime dependency. [SAE-SPLADE, SIGIR 2026](https://arxiv.org/abs/2604.21511) replaces vocabulary expansion with sparse learned concepts and reports comparable retrieval with better efficiency; it requires trained sparse representations and an inverted index, not a synonym list.

The current environment has CPU inference and about 9.7 GiB RAM, with no configured hosted answer-model credentials. CPU affinity exposes three logical CPUs, but cgroup `cpu.max=200000 100000` limits sustained execution to **two CPU equivalents**; model timing must account for that quota and concurrent jobs. Local retrieval comparisons are feasible. Trained agent, large long-context and VLM end-to-end scores require appropriate model execution; mocked callbacks are contract tests, not quality evidence.
