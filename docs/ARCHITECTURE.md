# Architecture (0.4)

```
Local source snapshot → bounded extraction → offsets/chunks → SQLite transaction
                                             ↓                 ↓
                                     optional ONNX vectors   FTS5 + indexed metadata
                                                               ↓
                                      filtered lexical/dense retrieval → RRF
                                                               ↓
                                     optional token/cross-encoder scoring → original context
                                                               ↓
                                exact evidence / quote-checked generation / Decimal
```

`Index` owns documents, sections, chunks, vectors, metadata lookups and extraction/model signatures. Foreign keys cascade removals, FTS triggers stay in the same transaction, and WAL readers see a committed snapshot while ingestion runs. Invalid parsing, embeddings or writes roll back every changed document. Directory-scan permission errors stop ingestion rather than silently deleting apparently missing sources. Embedding batches span rows/pages and changed documents within the transaction, retaining at most 32 pending chunks. Incremental ingest hashes source/sidecar snapshots; unchanged sources skip parsing and encoding. The index records a generation only when content changes.

`sources` keeps PDF pages, CSV rows and JSON records distinct. CSV headers repeat for every row. JSON number lexemes are preserved as strings in the rendered evidence. Offsets refer to the stored extracted/rendered section, not raw PDF bytes or raw CSV/JSON syntax. Plain text offsets match the original Unicode text. Overlapping chunks prefer line/sentence boundaries, retain exact text and expand locally for clause/table context. Identical basenames in different directories remain separate documents. Queries fetch bounded original text windows through SQLite instead of copying complete sections per candidate. Existing incomplete schemas or missing FTS synchronization triggers are rejected. The supported 0.3 schema migrates atomically, adding an extractive context column and rebuilding the lexical index while preserving original sections, vectors and generation. NUL-containing extracted text is rejected to preserve window semantics. No synthetic LLM enrichment rewrites evidence.

Metadata values are explicit strings/integers. An indexed key/value table scopes both retrieval channels before ranking; filters are parameterized. Scoping is not authorization: this is a private single-user library, not a tenant-isolated service. Source order/FTS rowids resolve lexical cutoff ties; final fused/reranked ties use chunk IDs. Replacing tied chunks can change cutoff membership.

FTS5 performs lexical retrieval on disk. Dense retrieval normalizes vectors and scans them in 512-row batches, pruning block losers in NumPy before merging a bounded top-k heap. Every cutoff tie remains eligible for deterministic ID ordering. It is exact O(N×dimension), not ANN or a claim of constant latency at millions of chunks. Optional models use pinned ONNX/tokenizer assets with bounded CPU threads. Minibatches group similar text lengths and restore original output ordering; MiniLM uses batches of eight, E5 sixteen and the reranker eight. MiniLM is general English, with truncation at 256 tokens; optional E5 uses quantized weights and is an English asymmetric retrieval encoder with explicit query/passage prefixes and a 512-token limit. Neither is a domain-certified encoder; reranking is MS MARCO trained, truncates pairs at 512 tokens, and returns logits, not confidence. Benchmark domain performance before enabling it.

Repeated unfiltered dense queries may use a bounded in-memory matrix (default 64 MiB; zero disables it). Budget eligibility includes vector bytes, IDs and selection overhead. Generation, connection writes and SQLite data-version changes invalidate it; filtered queries stream scoped rows. SQLite remains the persistent source of truth. This improves warm scans, not model encoding or the first query of a short-lived CLI process.

Token late interaction changes the representation rather than merely switching a pooled embedding. ColBERT-small stores 96-dimensional token representations; GTE-ModernColBERT uses 128 dimensions. Candidate scores sum each query token's maximum cosine match over passage tokens. Original checkpoint prefixes, punctuation masks and query augmentation settings matter. The pinned root ONNX exports include trained projections; superficially similar backbone exports do not. These are candidate rerankers, not PLAID/ANN indexes, and cannot repair missing candidates.

`prepare-reranker` explicitly builds an optional `rerank_tokens` table in the same SQLite transaction. It stores normalized float32 token arrays, checkpoint signatures and hashes of the actual original passage/heading representation. Chunk deletion cascades into token deletion; checkpoint changes replace the cache atomically. Missing/mismatched hashes fall back to encoding that passage without writing during a read query; malformed cached arrays fail. Queries encode only the question when the candidate cache is complete. This increases disk/indexing work and preserves the model representation; token-index size must be measured, not assumed equal to one vector per chunk. Opening an existing schema-3 index performs no schema-state write, so readers can open while a writer builds this cache.

`EmbeddingServer` separates model execution from storage via bounded OpenAI-compatible embedding requests. It can use contemporary self-hosted instruction-aware models such as Qwen3. Query instructions, model identity and an explicit commit/digest form the stored signature; the operator must verify that the server really serves that artifact. No credentials or endpoint addresses enter compatibility signatures. This is an opt-in network route; the built-in ONNX route remains local.

`Navigation` exposes scoped document metadata, a paginated original section directory, exact bounded reads and lexical/dense/hybrid search. IDs proposed by a planner are checked against the same metadata scope on every read. Model-directed navigation has bounded steps/output characters and a trace; it fails if the index version changes across steps. Final generation uses the existing original-quote and number/unit validation. This implements document-navigation/agent action infrastructure, not PageIndex's full hierarchical index or a trained GRASP/DeepRAG policy. `answer(context_order="source")` selects evidence by relevance within the same budget, then presents it in original document/section order for a DOS-style baseline. It does not assert an answer-accuracy gain without answer-model evaluation.

`answer` returns evidence by default and abstains when retrieval returns none. Optional generation receives a separate system instruction and bounded JSON evidence, must return only cited claims, and is rejected on invented source IDs, quotes, or numerical values/currencies/common scales/recognized measurement units. Explicit adjacent number/unit pairs must also agree when present in the cited quote. Numeric formatting may differ while Decimal values must agree; dollar symbols are not assumed to be USD. These checks are conservative and not exhaustive unit/semantic validation. It never displays uncited trailing prose. This proves cited text exists; it cannot prove a paraphrase follows logically, select the correct accounting period, or fully prevent prompt injection. `calculate` requires explicit source IDs, exact quotes, values and matching units; it uses reproducible Decimal operations rather than executing generated code. Operand meaning and scale remain caller responsibilities.

The 0.2 JSON/Chroma/LightRAG manifests, cleanup, graph rebuilds, LangChain/Ragas layers and their tests were removed together. Their split-state synchronization and vulnerable dependency paths are no longer part of the declared runtime. Historical audit evidence is retained; no old user store is automatically deleted. No web fetching, OCR, background branch creation or hidden model/service calls occur during ordinary core ingestion/search.

Opt-in contextual indexing prepends a bounded extractive Markdown heading hierarchy to the existing metadata/passage representation. Nested headings reset at their level; fenced code headings are ignored. It does not infer PDF structure, parse source-code ASTs, generate summaries or maintain conversation state. `Hit.context` is separate from original `Hit.text`; generation can quote only original evidence. Headers are indexing guidance, not independently verified evidence. Heading-rich inputs need domain evaluation before enabling it globally.

The same opt-in path stores original heading parent/child links and exact start/end ranges in an optional `heading_nodes` table. `Navigation.headings` browses this hierarchy under the fixed document scope; parent IDs cannot cross that scope. Source-section deletion cascades into tree deletion. This provides extractive book navigation without paid synthetic summaries; documents without ATX headings retain the original section/search fallback. Navigation can call the deterministic source-bound calculator and return structured computation provenance instead of letting a model invent arithmetic.

The lexical tokenizer preserves `+`, `#` and `_`, distinguishing language names and exact identifiers. When every query word is a stop word, standalone terms such as IT/OR still search; punctuation-only queries return no hits. Natural-language subword expansion for identifiers is not implemented. Returned context-window overlap, rather than only seed-chunk overlap, suppresses repeated evidence; this improves coverage but can widen retrieved material and reduce character precision.
