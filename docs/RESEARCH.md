# Retrieval research and decisions — 2026-10-02

Research used Exa searches for finance/accounting QA, legal span retrieval and retrieval/chunking work from **2025-10-02 through 2026-10-02**, plus established benchmarks. Reviewed 18 search-result slots, three additional CUAD licensing results and five primary paper pages. Search dates/claims were checked against original abstracts; this is an engineering synthesis, not a systematic literature review or reproduction of each paper.

| Primary source | Relevant evidence | Project decision |
| --- | --- | --- |
| [FinanceBench (2023)](https://arxiv.org/abs/2311.11944) | Financial QA mixes company/period scope, textual/tabular evidence and numerical reasoning; retrieval augmentation alone did not reliably answer the studied questions | Explicit metadata filters, row labels, original values, separate Decimal operations and no claim that cited prose is automatically correct |
| [FinQA (EMNLP 2021)](https://aclanthology.org/2021.emnlp-main.300/) | Expert-annotated numerical reasoning uses table/text evidence and executable programs | Use independent gold row IDs for a retrieval proxy; keep model-written code out of the arithmetic path |
| [LegalBench-RAG (2024)](https://arxiv.org/abs/2408.10343) | Precise minimal legal spans are more informative than broad document recall | Original offsets/locators, overlap-aware character precision/recall, bounded surrounding clause context |
| [ARQA (EACL Industry 2026)](https://aclanthology.org/2026.eacl-industry.63/) | Auditable table/text lookup, arithmetic and insight are distinct challenges; deterministic recomputation matters | Source-bound quoted operands; report retrieval separately from numerical execution and causal reasoning |
| [When Is Complex Chunking Worth It? (2026 preprint)](https://arxiv.org/html/2608.16586) | Expensive chunking did not consistently beat simple strategies; model/data/scale affect the tradeoff | Small bounded chunks and local original context, without paid synthetic enrichment or per-query LLM compression |
| [SciRet (2026 preprint)](https://arxiv.org/abs/2608.03860) | Hybrid/RRF can help; MS MARCO reranking hurt their scientific corpus. Their labels were derived from the hybrid system, limiting benchmark claims | Frozen independent FinQA/CUAD labels, measure the optional cross-encoder directly, keep reranking opt-in |
| [CUAD](https://www.atticusprojectai.org/cuad/) | Lawyer-supervised clause spans in commercial contracts, released CC BY 4.0 | Reproducible test-contract slice with original spans and explicit contract scope; attribution in the preparation script |

The design combines established methods rather than claiming a new trained retrieval model. Graph traversal, query expansion, trained chunk planners, fine-tuning and specialized financial/legal encoders can be useful, but were not added without controlled evidence that their quality gain warrants latency, maintenance and dependency cost. Large/model-specific production evaluations are still needed. CPU ONNX models were exercised on real public benchmark text; hosted answer generation was not evaluated without credentials or a representative user corpus.

## Context and broader domains — 2026-10-03

Used Exa to review 20 search-result slots across contextual retrieval, biomedical evaluation, code evaluation and asymmetric encoders, plus three primary pages. Results were checked against original repositories/model metadata and licensing; this is not a systematic review.

- [Anthropic contextual retrieval (2024)](https://www.anthropic.com/engineering/contextual-retrieval) situates chunks before lexical/dense encoding. Its reported reductions use LLM-generated context, other encoders and top-20 evaluation; they are not this project's scores. Implemented an inexpensive extractive heading variant, left opt-in, with original evidence kept separate.
- [SciFact (EMNLP 2020)](https://aclanthology.org/2020.emnlp-main.609/) and [BEIR](https://github.com/beir-cellar/beir) supply independent biomedical retrieval judgments. Run all 300 test queries against all 5,183 abstracts. This measures finding evidence, not support/refute classification or clinical answer safety. Original claims/annotations are CC BY 4.0, abstracts ODC-By 1.0; no raw dataset is redistributed.
- [E5 model card](https://huggingface.co/intfloat/e5-small-v2) requires `query:`/`passage:` prefixes and mean pooling. Added a pinned MIT quantized CPU ONNX option and a distinct query-encoding interface, preserving MiniLM compatibility. Published pretrained models may have encountered benchmark text; no encoder was trained or tuned here. Cosine scores/thresholds are not calibrated probabilities, especially across models.
- [COIR (ACL 2025)](https://aclanthology.org/2025.acl-long.1072/) shows that software retrieval needs varied text/code tasks and that established code datasets risk overfitting. This release adds exact identifier/language-name retrieval and original Python/SQL ingestion, with authored regressions. It does not claim a full COIR score or complete program understanding.
- [NFCorpus](https://www.cl.uni-heidelberg.de/statnlpgroup/nfcorpus/) has academic-use restrictions on its underlying NutritionFacts data. SciFact was selected instead of treating a mirror's license tag as blanket permission.

Next independent evaluations should cover clinical unanswerability, symbol/subword software queries, accounting execution semantics and time-sensitive trading documents. ANN/vector extensions, specialized rerankers and conversation/query planning require separate latency/quality evidence; exact filtered retrieval remains the reference route.
